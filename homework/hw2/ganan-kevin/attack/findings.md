# Part A — oracle-confirmed baseline findings

## Scope and Medium-filter limitation

The reviewed `labs/vuln-web/README.md`, `Dockerfile`, `test_vuln_web.py`,
`vulnweb_app.py`, and `seclab/targets.py` describe a deliberately vulnerable
app with three sinks and a fixed `/safe` endpoint. None of those files
implements or configures a Medium filter. The provided fixture tests send
baseline payloads directly to the sinks.

`confirm_template.py` now uses the actual course `seclab.attack` API
(`Payload`, `run_payloads`, and the oracle functions). It confirms the
baseline vulnerability effects.

## SQL injection — `do_login`

- **Baseline payload:** `admin' OR '1'='1` in the `user` field of `POST /login`.
- **Official oracle:** `seclab.attack.run_payloads` with
  `seclab.attack.contains_oracle("FLAG-sqli-9f2c-admin-session")`.
- **Confirmation meaning:** the seeded admin canary is returned. A changed
  status, SQL error, or altered response without the canary is insufficient.
- **OWASP 2021:** A03:2021 Injection — SQL injection.


## Reflected XSS — `do_reflect`

- **Baseline payload:** `<script>alert(1)</script>` in `GET /?name=`.
- **Official oracle:** `seclab.attack.run_payloads` with a custom oracle that
  requires a literal, unescaped `<script>` element in the response and rejects
  the HTML-encoded form `&lt;script&gt;`.
- **Confirmation meaning:** this is the exact response oracle required by the
  homework. It proves that executable script markup is returned unescaped; it
  is not the same as a separate browser event/JavaScript-execution test.
- **OWASP 2021:** A03:2021 Injection — cross-site scripting.


## Command injection — `do_ping`

- **Baseline payload:** `127.0.0.1; whoami` in `POST /ping`'s `host` field.
- **Official oracle:** `seclab.attack.run_payloads` with a custom JSON oracle
  requiring `injection_detected` to be `true`.
- **Confirmation meaning:** the teaching app detects a shell metacharacter in
  the command context and returns the `would_run` string.
- **OWASP 2021:** A03:2021 Injection — OS command injection.
- **Important scope statement:** this teaching application simulates shell
  interpretation. It does not invoke a shell or execute `whoami`; the oracle
  confirms the lab's simulated command-context effect only.


## Broken Access Control — A01:2021

The supplied app has no session, identity token, role, ownership model, or
authorization check. `do_login` contains SQL injection that changes the SQL
predicate; it does not establish a separate IDOR or broken role/ownership
check. On this source, A01 is not reachable as a distinct access-control
finding. A scanner reporting A01 must identify an actual authorization
mechanism and a policy violation; none is present in the supplied handlers.
